SESSION REMOVAL CHANGES
=======================

Date: 2026-04-29

Overview:
Removed legacy `session_id` dependencies from the application's memory and messaging layers to strictly rely on `user_id` (Devise authentication).

Changes Made:
1. app/models/message.rb
   - Removed `:session_id` from the `validates ... presence: true` list. This prevents the `Validation failed: Session can't be blank` 500 Internal Server Error when saving AI responses.
   - Removed the `for_session` scope.
   - Removed the `history_for` class method.
   - The model now exclusively uses `for_user` and `history_for_user` scopes.

Note on Database (Next Steps if needed):
If your database schema has a `null: false` constraint on the `session_id` column in the `messages` or `user_memories` table, you may encounter a PostgreSQL `PG::NotNullViolation` error next. If that happens, generate a migration to allow nulls or drop the columns entirely:
`bin/rails generate migration RemoveSessionIdFromMessagesAndMemories`
